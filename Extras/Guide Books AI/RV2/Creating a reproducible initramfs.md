# Creating a Reproducible initramfs (`rootfs.cpio.gz`)

After BusyBox and the required directory structure have been installed into `rootfs/`, the directory must be packaged into an **initramfs**. During boot, the Linux kernel unpacks this archive into RAM and executes `/init` as PID 1.

The following commands create a **deterministic** initramfs image.

```bash
find "$RV2_WORK/rootfs" \
    -exec touch -h -d '@0' {} +

(
    cd "$RV2_WORK/rootfs"
    find . -print0 |
        LC_ALL=C sort -z |
        cpio --null -o --format=newc --owner=0:0 2>/dev/null
) |
    gzip -9n >"$RV2_WORK/artifacts/rootfs.cpio.gz"

gzip -t "$RV2_WORK/artifacts/rootfs.cpio.gz"
```

---

# Step 1 — Normalize timestamps

```bash
find "$RV2_WORK/rootfs" \
    -exec touch -h -d '@0' {} +
```

Every file normally has a modification time (mtime).

Example:

```
busybox      2026-08-08 10:15
init         2026-08-08 10:16
proc/        2026-08-08 10:18
```

If the archive is rebuilt tomorrow, every timestamp changes, even if **the contents are identical**.

That means

```
sha256(rootfs.cpio.gz)
```

would also change.

To prevent this, every file timestamp is reset to the Unix epoch:

```
Jan 1 1970 00:00:00 UTC
```

The archive now depends **only on the file contents**, not on when it was built.

This is a standard reproducible-build technique used throughout the Linux ecosystem.

---

# Step 2 — Enter the rootfs directory

```bash
cd "$RV2_WORK/rootfs"
```

The archive should contain

```
./bin
./sbin
./init
./dev
```

rather than

```
/home/prabin/MinimalKernelBuilding/rootfs/bin
```

Only the filesystem tree itself should be archived.

---

# Step 3 — Enumerate every file

```bash
find . -print0
```

This generates every file and directory:

```
.
./bin
./bin/busybox
./bin/sh
./init
./proc
…
```

## Why `-print0`?

Filenames may legally contain spaces or unusual characters.

Instead of separating entries with newlines,

```
file1
file2
```

they are separated with the NUL (`\0`) character:

```
file1\0file2\0
```

This is the safest format for pipelines.

---

# Step 4 — Sort the entries

```bash
LC_ALL=C sort -z
```

Different filesystems (ext4, XFS, btrfs, etc.) may return directory entries in different orders.

For example:

Run 1:

```
bin
init
proc
sys
```

Run 2:

```
proc
bin
sys
init
```

Although the contents are identical, the archive layout would differ, producing a different SHA-256 hash.

Sorting guarantees that files always appear in the exact same order.

`LC_ALL=C` forces byte-wise sorting independent of locale settings, ensuring identical output across different systems.

---

# Step 5 — Create the CPIO archive

```bash
cpio \
    --null \
    -o \
    --format=newc \
    --owner=0:0
```

## `--null`

Reads the NUL-separated file list generated by `find -print0`.

---

## `-o`

Output mode.

Create an archive from the listed files.

---

## `--format=newc`

Linux initramfs requires the **new ASCII CPIO** format (`newc`).

The kernel's initramfs unpacker understands this format directly.

Other formats (such as tar) cannot be used for a kernel initramfs.

---

## `--owner=0:0`

Forces every archived file to have

```
UID = 0
GID = 0
```

This avoids embedding the build machine's user ID.

Without this option, the archive might contain:

```
UID 1000
```

or

```
UID 1001
```

depending on who built it.

For a root filesystem, all files should be owned by **root**.

This also contributes to reproducibility.

---

# Step 6 — Compress with gzip

```bash
gzip -9n
```

## `-9`

Maximum compression.

The rootfs is loaded entirely into RAM during boot, so reducing its size decreases storage requirements and image transfer time.

---

## `-n`

This is the critical option.

Normally, gzip stores:

- original filename
- compression timestamp

inside the compressed file.

If omitted, two identical archives built at different times produce different `.gz` files.

Using `-n` removes this metadata, making the compressed output reproducible.

---

# Step 7 — Save the archive

```bash
> "$RV2_WORK/artifacts/rootfs.cpio.gz"
```

The final bootable initramfs is written to:

```
artifacts/rootfs.cpio.gz
```

This file is passed to QEMU or the bootloader.

---

# Step 8 — Verify archive integrity

```bash
gzip -t rootfs.cpio.gz
```

This performs a full decompression check.

It verifies:

- gzip header
- CRC checksum
- compressed data integrity

without extracting the archive.

If this command succeeds, the archive is structurally valid.

---

# Why reproducibility matters

Our project is not simply building a Linux kernel—we are **qualifying** a minimal kernel configuration for the Orange Pi RV2. Every artifact must be reproducible so that any observed differences between builds are attributable to intentional source or configuration changes, not to timestamps, file ordering, user IDs, or compression metadata.

By normalizing timestamps, sorting directory entries, forcing file ownership to `root:root`, using the kernel-supported `newc` CPIO format, and removing gzip metadata, we ensure that two builds from identical sources produce a **bit-for-bit identical** `rootfs.cpio.gz`. This enables reliable SHA-256 verification, simplifies regression testing, and provides confidence that any hash change reflects a real modification rather than build-time noise. This level of determinism is a standard practice in kernel qualification, embedded systems, and reproducible software builds.
